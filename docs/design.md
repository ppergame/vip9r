# vip9r — design

Working notes on architecture and mechanics. AGENTS.md holds the framing and the
decisions; this holds the detail those decisions imply. Maintained by the agent.

## The module

Freestanding `wasm32-unknown-unknown`, no WASI / Emscripten / autogenerated FFI.
Decode is `no_std` Rust (no libc); hand-rolled shims cover the handful of libc
calls minih264 makes. Per-GOP bump allocator, reset every GOP. Streaming I/O at
frame granularity (push packet → get frame). Imports kept near-zero beyond
`abort`/`log`; export surface stays small. Manual ad-hoc bindings.

- **Decode — from spec, no seed.** Written from the VP9 spec, pragmatically
  clean-room: match libvpx's intermediate values first, read its source only to
  disambiguate the spec, never copy. Formally a derived work of libvpx.
- **Encode — minih264 seed (C).** Single-file, public domain. Harness and
  showcase, not the focus; replacing it is a later campaign if quality stings.
- **Safety.** Safe-ish Rust; `unsafe` only for integration or performance. The
  wasm sandbox is the ultimate safety boundary.
- **SIMD.** Per-kernel, not a global phase. Each kernel lands scalar-from-spec
  first (provable bit-exact against its golden), then gets SIMD128. Relaxed-simd
  (breaks determinism and host validation) and threads (benchmarking pain) are
  deferred to M5.

## The bench ABI ("run this slot")

Agents supply only wasm exports conforming to a fixed ABI; the trusted JS driver
discovers and times them. No agent-authored harness or JS.

- The module exports `bench_list()` (slot descriptors) and
  `bench_run(slot_id, input_ptr, iters)` alongside the decode/encode API. A
  grinder microbenchmarking a stage adds a slot export wired to it.
- Slot inputs are captured blobs. A harness capture mode shims the DSP function
  table and snapshots real stage inputs from corpus clips.
- The driver times each frame call and reports the distribution, not the average
  — catches the "fast average, slow worst frame" case.
- One oracle run type covers everything: `full | frame | stage:<slot>` plus a
  clip or blob reference.

## The oracle

A daemon on the host. It owns adb and the device; agents never touch either. It
answers two questions: *is it correct* and *is it faster*.

### Correctness — libvpx goldens

Instrumented libvpx emits per-kernel goldens (stage-level) and full decoded
frames (clip-level). A candidate runs on host d8 and is correct iff bit-exact
against the relevant golden. Where the per-kernel tap sits — libvpx's `vpx_dsp`
rtcd surface is the candidate, with known mismatches — is the boundary analysis
below.

Stage goldens are what make from-spec implementation tractable: one wrong bit
localizes to a kernel instead of smearing into frame garbage. Conformance vectors
ship their own full goldens; libvpx generates goldens for the performance corpus,
which ships none.

The **reconstruct half** (leaf kernels — IDCT, prediction, loop filter, …)
verifies at stage granularity against these goldens. The **parse half** (bool
decoder, header, modes, MVs, context adaptation) has no clean leaf golden and
verifies at full-frame granularity plus whatever libvpx structs are tappable.

### Timing — V8 everywhere, three endpoints

1. **Host d8** — cheap prefilter after correctness passes; weeds out obvious
   losers for free.
2. **Simulator d8** — arm64 simulator build (`target_cpu="x64"`,
   `v8_target_cpu="arm64"`), real arm64 TurboFan codegen on the host with
   `--print-wasm-code` disclosing the actual machine code. No device contention;
   the main feedback loop for "did my HLL pattern produce the native code I
   wanted."
3. **Device d8** — ground truth. Rooted Pixel 9a, d8 pinned to the big-core
   cluster via taskset, cpufreq locked below the throttle point. Always A/B
   interleaved against current main; reports deltas with confidence intervals,
   never bare absolutes.

Economics: host correctness is free and runs on every proposal; host timing is
the cheap prefilter; device time is scarce and budgeted by the explore step.

Honesty mechanics:
- A per-stage win must be reconfirmed against full-decode wall time before it
  enters the record — stage gains that vanish in context (icache, bandwidth)
  don't count.
- The oracle accepts ad-hoc wasm blobs for exploration, but only **rev-built
  runs** — built by the oracle itself, in the nix container, from a VCS rev — are
  citable in the changelog or survive review. Reproducible at rev granularity, no
  run-id ledger indirection.

## The hierarchy

- **Top — interactive session (human + agent).** Owns intent, the harness, the
  oracle, honesty policing. All measurement infrastructure is built and trusted
  here; agent-built harness would undermine the honesty story.
- **Explore step.** Manually triggered, one context window of strategy. Reads the
  ledgers, spawns grinders. Parallelism without a formal merge queue: one
  grinder runs on the phone while others think; the oracle queues device requests.
  - *implement* — drive from-spec coverage: pick unimplemented or
    not-yet-bit-exact kernels, gate on stage goldens. Correctness first, then
    cost. Host-only, barely touches device budget.
  - *optimize* — pick performance hypotheses, spend the device-time budget
    against measured deltas.
- **Grinders.** Non-interactive codex in transient nix containers (host store
  shared, toolchain exposed). Trimmed environment: the subtask spec, specs/docs
  (the VP9 spec is first-class), an oracle handle, web access, a project
  subfolder. Nothing else.
- **Review step.** Manually triggered, separate pass before push. Re-runs the
  claim at rev granularity (measured delta for optimize, bit-exactness for
  implement) and checks the held-out clip for corpus overfitting.

## The record

- **Per-kernel ledger** (materializes when M1 kernel work starts). Two tracks per
  kernel — *correctness*: implemented? bit-exact vs golden at which rev? spec gaps
  / unhandled cases. *Performance*: tried / measured / rejected-because /
  suspected-headroom. Stateless strategy agents re-read it each explore step;
  intelligence lives in artifacts, not long-running processes.
- **`docs/log.md`** — human-facing changelog/narrative. Each entry: rev, the
  hypothesis and measured delta, or the first-bit-exact milestone.

## Corpus

- **Correctness:** WebM/libvpx conformance vectors, profile 0 / 8-bit subset.
- **Performance:** a handful of 720p clips with distinct character (high-motion
  sport, film grain, screen content, talking head), libvpx-encoded at
  YouTube-ish settings. At least one stays held out for the review step.

## Open design questions

- Golden harness: which `vpx_dsp` boundaries tap cleanly vs fused; how to verify
  the parse half (entropy / modes / MVs / context) — full-frame plus which
  tappable structs, at what granularity.
- Grinder spec template: which spec excerpts and derived per-kernel notes for
  implement mode; V8 codegen notes and SIMD128→NEON references for optimize mode.
- Device-time and token budget per explore step, and cadence.
- Grinder commit/workspace mechanics under jj (colocated with git; top-level
  commits are the human's).
