# d8 toolchain

This project uses Google-published V8 `d8` bundles as the cheap WebAssembly
execution, inspection, and timing surface before a full browser/device harness
exists.

## What each binary is for

- `D8_LINUX64`: fast host smoke loop. It can run Wasm and control Wasm tiering,
  but it emits host x64 code only. Flags such as `--target-arch=arm64` do not
  make this binary cross-compile Wasm to ARM.
- `D8_ANDROID_ARM64`: AArch64 target code. Run it on an ARM64 device or under
  `qemu-aarch64` user emulation with a minimal Android runtime root.
- `D8_ANDROID_ARM32`: ARMv7 target code. Run it on an ARM32-capable Android
  target or under `qemu-arm` user emulation with a minimal Android runtime root.

The devshell exports both bundle roots and executable paths:

```sh
V8_LINUX64
V8_ANDROID_ARM32
V8_ANDROID_ARM64
D8_LINUX64
D8_ANDROID_ARM32
D8_ANDROID_ARM64
```

Use JavaScript `version()` for a portable version check. Some Android `d8`
builds do not accept `--version`.

```sh
$D8_LINUX64 -e 'print(version()); quit(0)'
```

When copying Android `d8` to a physical device, copy `icudtl.dat` and
`snapshot_blob.bin` from the same V8 bundle into the same directory as `d8`, and
run `d8` from that directory. Otherwise Android `d8` may fail at startup with an
ICU initialization error.

## Bumping the flake pins

`nix/v8.nix` pins three canary artifacts:

- `v8-linux64-rel`
- `v8-android-arm32-rel`
- `v8-android-arm64-rel`

Each pin needs:

- `version`
- GCS object `generation`
- Nix fixed-output `hash`

Android can lag Linux. Prefer matching versions when all three exist, but pin
the newest usable artifact per target when they do not.

List available versions for one artifact:

```sh
artifact=v8-android-arm64-rel

python3 - "$artifact" <<'PY'
import json
import re
import sys
import urllib.parse
import urllib.request

artifact = sys.argv[1]
token = None
rows = []

while True:
    query = {
        "prefix": f"official/canary/{artifact}-",
        "fields": "items(name,generation),nextPageToken",
        "maxResults": "1000",
    }
    if token:
        query["pageToken"] = token

    url = "https://storage.googleapis.com/storage/v1/b/chromium-v8/o?" + urllib.parse.urlencode(query)
    data = json.load(urllib.request.urlopen(url))

    for item in data.get("items", []):
        match = re.search(rf"/{re.escape(artifact)}-(\d+\.\d+\.\d+)\.zip$", item["name"])
        if match:
            version = match.group(1)
            rows.append((tuple(map(int, version.split("."))), version, item["generation"]))

    token = data.get("nextPageToken")
    if not token:
        break

for _, version, generation in sorted(rows)[-30:]:
    print(version, generation)
PY
```

Prefetch a selected artifact:

```sh
artifact=v8-android-arm64-rel
version=15.1.159
generation=1782060481347578
url="https://storage.googleapis.com/chromium-v8/official/canary/${artifact}-${version}.zip?generation=${generation}"

nix store prefetch-file --unpack --name "${artifact}-${version}" --json "$url"
```

Copy the returned `hash` into `nix/v8.nix` with the selected `version` and
`generation`.

Smoke-test after editing `nix/v8.nix`:

```sh
nix develop -c sh -c '$D8_LINUX64 -e "print(version()); print(typeof WebAssembly); quit(0)"'
```

For Android pins, rebuild or reuse the qemu runtime roots below and smoke-test
with the target binary.

## Android under qemu user emulation

The Android `d8` bundles are PIE Android ELFs:

- arm64 interpreter: `/system/bin/linker64`
- arm32 interpreter: `/system/bin/linker`
- dynamic dependencies: `libdl.so`, `libm.so`, `libc.so`

Use the Android dynamic linker. NDK Bionic library prebuilts are not enough
because they do not include `/system/bin/linker{,64}`. Substituting glibc
loaders or symlinking the linker to `libc.so` is not a valid runtime.

Do not create real host `/system` paths. Build a small runtime root and expose
it with `bwrap`.

Recommended cache location:

```sh
export VIP9R_D8_ROOTS="${XDG_CACHE_HOME:-$HOME/.cache}/vip9r/d8"
mkdir -p "$VIP9R_D8_ROOTS"
```

### ARM32 runtime root

Use an Android API 21 `armeabi-v7a` system image. API 21 satisfies the current
arm32 `d8` minimum Android API note and avoids an API 25 Bionic/qemu-arm failure
around `personality(0xffffffff)`.

Build the system image:

```sh
ARM32_IMAGE=$(
  NIXPKGS_ALLOW_UNFREE=1 NIXPKGS_ACCEPT_ANDROID_SDK_LICENSE=1 \
  nix build --impure --no-link --print-out-paths --expr '
    let
      pkgs = import (builtins.getFlake "nixpkgs") {
        system = "x86_64-linux";
        config.allowUnfree = true;
        android_sdk.accept_license = true;
      };
      android = pkgs.androidenv.composeAndroidPackages {
        platformVersions = [ "21" ];
        abiVersions = [ "armeabi-v7a" ];
        includeSystemImages = true;
        systemImageTypes = [ "default" ];
      };
    in builtins.head android.system-images
  '
)

ARM32_SYSTEM_IMG="$ARM32_IMAGE/libexec/android-sdk/system-images/android-21/default/armeabi-v7a/system.img"
ARM32_ROOT="$VIP9R_D8_ROOTS/android-arm32-api21"
mkdir -p "$ARM32_ROOT/system/bin" "$ARM32_ROOT/system/lib"
```

Extract the minimal files:

```sh
rm -f \
  "$ARM32_ROOT/system/bin/linker" \
  "$ARM32_ROOT/system/lib/libc.so" \
  "$ARM32_ROOT/system/lib/libdl.so" \
  "$ARM32_ROOT/system/lib/libm.so"

nix shell nixpkgs#e2fsprogs -c debugfs -R \
  "dump -p /bin/linker $ARM32_ROOT/system/bin/linker" \
  "$ARM32_SYSTEM_IMG"

for lib in libc.so libdl.so libm.so; do
  nix shell nixpkgs#e2fsprogs -c debugfs -R \
    "dump -p /lib/$lib $ARM32_ROOT/system/lib/$lib" \
    "$ARM32_SYSTEM_IMG"
done
```

Run arm32 `d8`:

```sh
nix shell nixpkgs#qemu -c bwrap \
  --ro-bind /nix /nix \
  --ro-bind "$ARM32_ROOT/system" /system \
  --tmpfs /tmp \
  --proc /proc \
  --dev /dev \
  --chdir "$(dirname "$D8_ANDROID_ARM32")" \
  qemu-arm "$D8_ANDROID_ARM32" \
  -e 'print(version()); print(typeof WebAssembly); quit(0)'
```

### ARM64 runtime root

Modern arm64 emulator images store the Android runtime linker and Bionic
libraries inside `com.android.runtime.apex`, itself inside the dynamic `super`
partition. Extract the runtime APEX and bind both the canonical APEX path and a
legacy `/system` fallback.

Build an API 36 `google_apis` arm64 image:

```sh
ARM64_IMAGE=$(
  NIXPKGS_ALLOW_UNFREE=1 NIXPKGS_ACCEPT_ANDROID_SDK_LICENSE=1 \
  nix build --impure --no-link --print-out-paths --expr '
    let
      pkgs = import (builtins.getFlake "nixpkgs") {
        system = "x86_64-linux";
        config.allowUnfree = true;
        android_sdk.accept_license = true;
      };
      android = pkgs.androidenv.composeAndroidPackages {
        platformVersions = [ "36" ];
        abiVersions = [ "arm64-v8a" ];
        includeSystemImages = true;
        systemImageTypes = [ "google_apis" ];
      };
    in builtins.head android.system-images
  '
)

ARM64_SYSTEM_IMG="$ARM64_IMAGE/libexec/android-sdk/system-images/android-36/google_apis/arm64-v8a/system.img"
ARM64_ROOT="$VIP9R_D8_ROOTS/android-arm64-api36"
WORK="$(mktemp -d)"
mkdir -p \
  "$ARM64_ROOT/system/bin" \
  "$ARM64_ROOT/system/lib64" \
  "$ARM64_ROOT/apex/com.android.runtime/bin" \
  "$ARM64_ROOT/apex/com.android.runtime/lib64/bionic"
```

Extract the logical `system` partition from the image:

```sh
SUPER_START=$(
  nix shell nixpkgs#util-linux nixpkgs#jq -c sh -c \
    'sfdisk --json "$1" | jq -r ".partitiontable.partitions[] | select(.name == \"super\") | .start"' \
    sh "$ARM64_SYSTEM_IMG"
)

SUPER_SIZE=$(
  nix shell nixpkgs#util-linux nixpkgs#jq -c sh -c \
    'sfdisk --json "$1" | jq -r ".partitiontable.partitions[] | select(.name == \"super\") | .size"' \
    sh "$ARM64_SYSTEM_IMG"
)

dd if="$ARM64_SYSTEM_IMG" of="$WORK/super.img" bs=512 skip="$SUPER_START" count="$SUPER_SIZE" status=progress
nix shell nixpkgs#android-tools -c lpunpack "$WORK/super.img" "$WORK/lp"
```

Extract and unpack the runtime APEX:

```sh
nix shell nixpkgs#e2fsprogs -c debugfs -R \
  "dump -p /system/apex/com.android.runtime.apex $WORK/com.android.runtime.apex" \
  "$WORK/lp/system.img"

nix shell nixpkgs#unzip -c unzip -p "$WORK/com.android.runtime.apex" apex_payload.img > "$WORK/apex_payload.img"
```

Extract the minimal runtime files:

```sh
rm -f \
  "$ARM64_ROOT/apex/com.android.runtime/bin/linker64" \
  "$ARM64_ROOT/apex/com.android.runtime/lib64/bionic/libc.so" \
  "$ARM64_ROOT/apex/com.android.runtime/lib64/bionic/libdl.so" \
  "$ARM64_ROOT/apex/com.android.runtime/lib64/bionic/libm.so" \
  "$ARM64_ROOT/system/bin/linker64" \
  "$ARM64_ROOT/system/lib64/libc.so" \
  "$ARM64_ROOT/system/lib64/libdl.so" \
  "$ARM64_ROOT/system/lib64/libm.so"

nix shell nixpkgs#e2fsprogs -c debugfs -R \
  "dump -p /bin/linker64 $ARM64_ROOT/apex/com.android.runtime/bin/linker64" \
  "$WORK/apex_payload.img"

for lib in libc.so libdl.so libm.so; do
  nix shell nixpkgs#e2fsprogs -c debugfs -R \
    "dump -p /lib64/bionic/$lib $ARM64_ROOT/apex/com.android.runtime/lib64/bionic/$lib" \
    "$WORK/apex_payload.img"
done

cp "$ARM64_ROOT/apex/com.android.runtime/bin/linker64" "$ARM64_ROOT/system/bin/linker64"
cp "$ARM64_ROOT/apex/com.android.runtime/lib64/bionic/"*.so "$ARM64_ROOT/system/lib64/"
```

Run arm64 `d8`:

```sh
nix shell nixpkgs#qemu -c bwrap \
  --ro-bind /nix /nix \
  --ro-bind "$ARM64_ROOT/system" /system \
  --ro-bind "$ARM64_ROOT/apex" /apex \
  --tmpfs /tmp \
  --proc /proc \
  --dev /dev \
  --chdir "$(dirname "$D8_ANDROID_ARM64")" \
  qemu-aarch64 "$D8_ANDROID_ARM64" \
  -e 'print(version()); print(typeof WebAssembly); quit(0)'
```

The current arm64 root emits a linker warning about missing
`/linkerconfig/ld.config.txt`. It is harmless for `d8` with the minimal Bionic
set above.

## Wasm tier controls

Useful flags:

```sh
# Force Liftoff baseline and prevent tier-up.
--liftoff-only --no-wasm-tier-up

# Force TurboFan for Wasm.
--no-liftoff

# Exercise tier-up synchronously.
--wasm-tiering-budget=1 --wasm-sync-tier-up

# Print Wasm code metadata for one declared function.
--print-wasm-code --print-wasm-code-function-index=0
```

`--print-wasm-code` confirms the compiler tier and instruction address range.
The current pinned V8 bundles were built with `disassembler:false`, so this flag
does not print instruction text.

`--trace-turbo --trace-turbo-path=/out --trace-turbo-filter='*wasm*'` produces
target-specific compiler sequence JSON. This is useful for seeing instruction
selection and register allocation (`ArmAdd`, `Arm64Add32`, etc.) without raw
machine-code bytes.

## Profiling Android d8 Wasm

For physical-device attribution, use `simpleperf` plus V8's perf map output:

```sh
cd /data/local/tmp/vip9r/bin
simpleperf record \
  -f 1000 \
  -o /data/local/tmp/vip9r/profiles/simpleperf.data \
  -- \
  ./d8 \
    --no-liftoff \
    --perf-basic-prof \
    --perf-basic-prof-path=/data/local/tmp \
    --module \
    /data/local/tmp/vip9r/runs/<run-id>/golden.js -- \
    /data/local/tmp/vip9r/runs/<run-id>/vip9r.wasm \
    /data/local/tmp/vip9r/media/bear-vp9.ivf
```

Report:

```sh
simpleperf report \
  -i /data/local/tmp/vip9r/profiles/simpleperf.data \
  --sort dso,symbol \
  -n \
  --percent-limit 0.1
```

`--perf-basic-prof` writes `perf-<pid>.map` with JIT code ranges and Wasm
function names. Keep `--perf-basic-prof-path` on a path visible to
`simpleperf report`; `/data/local/tmp` worked on Pixel 9a and Google TV
Streamer. Raw symbols look like:

```text
JS:_ZN5vip9r11tile_syntax20inter_predict_sample17h...E-30-turbofan
```

The number before `-turbofan` is the declared Wasm function index. Demangle the
Rust symbol for readable reports.

Sampling rate is workload-dependent. Use higher rates for short probes. If
`simpleperf` switches to user-space cycles only:

```text
Can't record kernel samples, switch to cpu-cycles:u
```

That is acceptable for Wasm/JIT attribution.

`--prof` alone does not name user Wasm functions usefully; pair it with
`--perf-basic-prof` if using V8 tick samples.

Profiling output is not ratchet evidence. Use it to choose optimization targets;
reconfirm changes with full-decode timing.

## Getting native ARM assembly for Wasm

`--perf-prof` writes a perf jitdump file containing the raw machine-code bytes
of every JIT-compiled function, including Wasm functions named with their
mangled Rust symbol and declared function index. No live-process memory
extraction is needed. Verified end-to-end with the arm64 Android pin under
qemu-user: a full `bear-vp9.ivf` golden decode passes in ~8 s and yields 52
vip9r TurboFan records.

The Android builds default `--perf-prof-path` (and `--perf-basic-prof-path`) to
`/data/local/tmp`. If that directory does not exist in the sandbox, V8
CHECK-crashes at startup (`perf_output_handle_ != nullptr`, surfacing as a qemu
internal SIGTRAP). Point the flag at a bound writable directory:

```sh
OUT=$(mktemp -d)
nix shell nixpkgs#qemu -c bwrap \
  --ro-bind /nix /nix \
  --ro-bind "$ARM64_ROOT/system" /system \
  --ro-bind "$ARM64_ROOT/apex" /apex \
  --bind "$OUT" /out \
  --tmpfs /tmp \
  --proc /proc \
  --dev /dev \
  --chdir "$(dirname "$D8_ANDROID_ARM64")" \
  qemu-aarch64 -cpu cortex-a55 "$D8_ANDROID_ARM64" \
  --no-liftoff --perf-prof --perf-prof-path=/out \
  --module driver.js -- module.wasm input.ivf
```

Only functions V8 actually compiled produce records, and TurboFan inlining is
feedback-driven, so drive representative work (a full golden decode) before
reading the dump.

Jitdump layout: 40-byte header (`u32` magic `0x4A695444`, `u32` version, `u32`
header_size, `u32` elf_mach, then padding/timestamp fields up to header_size),
followed by records. A JIT_CODE_LOAD record is id 0: `u32` id, `u32`
total_size, `u64` timestamp, `u32` pid, `u32` tid, `u64` vma, `u64` code_addr,
`u64` code_size, `u64` code_index, NUL-terminated name, then `code_size` bytes
of machine code. Wasm names look like
`JS:_ZN5vip9r...17h...E-<index>-turbofan`.

Disassemble extracted bytes with all-target binutils:

```sh
# ARM32
nix shell nixpkgs#binutils-unwrapped-all-targets -c \
  objdump -D -b binary -m arm --adjust-vma="$CODE_ADDR" code.bin

# ARM64
nix shell nixpkgs#binutils-unwrapped-all-targets -c \
  objdump -D -b binary -m aarch64 --adjust-vma="$CODE_ADDR" code.bin
```

Expect V8 prologue/epilogue around the Wasm operations (`bti c`/`pacibsp`
hints on arm64) and constant-pool data at the end of a function disassembling
as garbage.

### CPU feature fidelity

For a fixed d8 binary, Wasm codegen depends on the probed CPU feature set
(`getauxval(AT_HWCAP)`/`HWCAP2` on arm64), not on the CPU model beyond those
bits. V8 arm64 probes JSCVT, DOTPROD, LSE, PMULL1Q, FP16; DOTPROD (`asimddp`)
is the only one plausibly relevant to vip9r codegen. qemu-user defaults to
`-cpu max`, which advertises more features than the physical devices. Pin
`-cpu` to a model matching the target device and compare against the device's
`Features` line from `adb shell cat /proc/cpuinfo` when bumping V8 pins or
adding a device.

## Known failure modes

- Missing `/system/bin/linker{,64}`: qemu reports it cannot open the Android
  interpreter. Build and bind the minimal runtime root.
- NDK Bionic libraries only: insufficient; the dynamic linker is missing.
- glibc loader with Bionic libs: not a valid substitute for Android's linker.
- API 25 ARM32 Bionic under qemu-arm: current qemu returns `ENOSYS` for
  `personality(0xffffffff)`, which that Bionic treats as fatal. Use API 21 for
  the arm32 qemu root.
- `--perf-prof`/`--perf-basic-prof` under qemu/bwrap: the Android builds
  default both output paths to `/data/local/tmp`; when absent in the sandbox,
  V8 CHECK-crashes at startup and qemu reports an internal SIGTRAP. Bind a
  writable directory and pass the path flag. An earlier session read this
  crash-adjacent failure as "jitdump lacks Wasm records"; that was wrong — see
  the assembly section above.
